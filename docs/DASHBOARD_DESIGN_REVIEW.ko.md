# 대시보드 디자인 검수

검수일: 2026-09-10

기준: `DESIGN.md`. 대상: `backend/dashboard/static/` 및 실행 중인 `http://127.0.0.1:9400/`.

판정: 기본 디자인 방향은 일치한다. 아래 표는 최초 검수 기록이며, 후속 요청에 따라 4건의 토큰 차이를 `dashboard.css`에 수정했다: 검색 입력 16px, 활성 기본 버튼의 pressed 상태, trace 14px, 모달 그림자 `0 16px 48px rgba(0,0,0,.12)`.

## 발견 사항

| 우선순위 | 항목 | 관찰 및 근거 | 수정 방향 |
|---|---|---|---|
| P2 | 검색 입력 글자 크기 | `dashboard.css:213`에서 검색 입력을 13px로 덮어쓴다. 390px 화면에서도 계산값 13px를 확인했다. `DESIGN.md:295`의 기본 UI 및 text-input은 16px다. 다른 설정 입력은 16px여서 일관성도 깨진다. | 검색 입력을 16px로 통일한다. |
| P2 | 기본 버튼의 pressed 상태 누락 | `dashboard.css:181`은 `:hover`에만 primary-deep를 지정한다. CSS 전체에 `:active` 정의가 없다. `DESIGN.md:359`는 눌림 상태에 primary-deep를 요구한다. 마우스에서는 hover가 가려 주지만 키보드·터치에서 명시적인 눌림 표현을 보장하지 않는다. | `.primary-button:active:not(:disabled)`에 primary-deep를 지정한다. |
| P3 | 코드/로그 글자 크기 | `dashboard.css:320`의 `.trace-output`은 12px/1.5다. `DESIGN.md`의 typography.code와 code-block은 14px/1.5를 정의한다. 배경·글꼴·패딩·반경은 일치한다. 이 항목은 소스 검토 결과이며 실제 trace를 펼쳐 검증하지 않았다. | trace 글자 크기를 14px로 조정한다. |
| P3 | 모달 그림자 강도 | `dashboard.css:199`는 `0 24px 72px rgba(0,0,0,.2)`를 사용한다. 경험 초기화 대화상자에서도 같은 계산값을 확인했다. `DESIGN.md:332`의 모달 elevation은 `0 16px 48px rgba(0,0,0,.12)`다. | 모달 그림자를 기준 값으로 통일한다. |

## 추가 관찰

- Codex 사용량 카드가 1개일 때도 `.codex-usage-windows`가 2열을 유지해 오른쪽에 빈 공간이 남는다 (`dashboard.css:77`). 실제 데스크톱 화면에서 주간 한도 카드 1개로 확인했다. 명시적 디자인 위반은 아니지만, 카드 수에 따른 가변 열 또는 단일 카드 전체 폭 처리가 자연스럽다.
- 글꼴 스택은 Circular·Inter 등을 선언하지만 HTML/CSS에 웹폰트 로딩은 없다. 설치된 글꼴에 따라 외형이 달라질 수 있다. 실제 렌더링 폰트를 확정하지 않았으므로 결함으로 단정하지 않는다.
- 마케팅 페이지용 hero·가격표·햄버거 내비게이션 규칙은 운영 대시보드에 그대로 적용하지 않았다. 어두운 리소스 패널은 문서에서 허용하는 제품 UI의 dark surface로 판단했다.

## 확인한 적합 항목

- 흰 페이지 배경, near-black 본문, emerald primary, 회색 경계선.
- 기본 버튼의 어두운 글자, 6px 반경, 14px/500 글꼴, 8px 16px 패딩.
- 주요 설정 카드의 12px 반경·32px 패딩·1px 경계선.
- 제목의 500 굵기 및 주요 제목의 음수 자간.
- 입력 필드의 기본 16px 글자와 38px 이상 높이, 주요 버튼의 36px 이상 높이.
- focus-visible 및 reduced-motion 대응 규칙.
- 목록·상세 화면: 320px와 390px에서 DOM 경계 측정상 가로 넘침 없음.
- 목록 화면: 768px에서 DOM 경계 측정상 가로 넘침 없음.
- 상세 진입·목록 복귀, 경험 초기화 모달 열기·취소 정상 동작.

## 검수 범위와 한계

데스크톱은 스크린샷으로 시각 확인했다. 모바일·태블릿은 브라우저 viewport override와 DOM 계산값 중심으로 확인했다. 모바일 스크린샷이 계산된 레이아웃과 다르게 캡처되어 모바일 시각 검수 완료로 간주하지 않는다. 전체 상태 조합·실기기 터치·스크린리더·명암비 전수 검사는 수행하지 않았다.

실행 화면에 재시작 필요 안내가 있어, 현재 백엔드 동작과 작업 트리의 최신 코드가 완전히 같다고 가정하지 않았다. 솔버 실행, 메시지 전송, 설정 저장, 데이터 삭제는 수행하지 않았다. 브라우저 크기 override는 검수 후 복원했다.
